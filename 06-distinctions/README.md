# 06 Distinctions

Perceptual tools. One file each.

## Why this exists

This may become the most valuable directory in the repository.

A distinction is not a definition and not a belief. It is an instrument for seeing. Before you have it, a situation is undifferentiated; after you have it, the situation visibly contains a thing you could not previously pick out, and you cannot go back to not seeing it. Someone who has the distinction *constraint* looks at a struggling operation and sees one place where the whole system is limited. Someone without it sees a lot of problems.

That is why distinctions get their own folder rather than being scattered through prose. They are the working parts. Most of what the Architecture actually does for a person is hand them a set of instruments and let them look again at something they thought they already understood. A book explains; a distinction equips.

Each one is also a unit of transfer. A distinction can be taught in a paragraph and used the same afternoon, which makes this folder the most directly useful thing here for anyone else.

## What belongs here

One markdown file per distinction. The working set includes:

Production Function, Constraint, Thread-Pulling, Forward Chaining, Property Rights, Value Creation, Value Capture, Institution, Organization, Attention, Realm of Possibility, Conviction, Beauty.

Each file should establish four things:

- **what it means**, stated tightly enough to be usable rather than merely agreeable
- **what becomes visible once you possess it**, which is the real test and the hardest part to write
- **examples**, concrete and preferably drawn from cases in this repository
- **related distinctions**, including the ones it is most often confused with

Say where it came from when the lineage is known. Name the boundary where it stops applying. A distinction that applies to everything distinguishes nothing.

## What does not belong here

**Distinctions are not principles.** A principle asserts something enduring about how inquiry and creation work, and could in principle be wrong. A distinction makes something visible, and is judged by whether it does. "Beauty is evidence of coherence" is a principle and lives in `07-principles/`. *Beauty*, as a thing you learn to notice and read, is a distinction and lives here. Keeping the two folders clean of each other is what keeps both useful.

No essays. If a file has grown into an argument, the argument belongs in `10-narrative/` and this file should return to being an instrument.

No terminology for its own sake. A new word that renames something already visible adds nothing and costs the reader. The test for admission is that the word lets you see something you could not see before.

## How it relates

Drawn from the raw material in `00` through `05`, especially the discovery sessions where distinctions get named for the first time, usually badly. Supplies the working vocabulary for `04-case-studies/`, which is where distinctions are tested against real situations, and for `09-kernel/`, which cannot be written without them.

Expect churn early and stability later. A distinction that keeps getting redefined has not been found yet; it is still being approached.
