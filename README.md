# Architecture for Creation

This repository is not a book. It is the source from which books, and much else, will be generated.

The Architecture for Creation is a body of thought about how creation actually works: how a person moves from noticing something real, to seeing it clearly, to conviction, to building something in the world. It emerged unexpectedly, in the middle of an attempt to rewrite a short biography, and it has been growing since. This repository is where it lives.

Think of it as an intellectual operating system. A book is an application. So is a course, a talk, a website, a company narrative, an investor deck, a bio. Applications come and go, are rewritten for new audiences, and go out of date. The operating system underneath them is what has to be right.

## Three simultaneous purposes

The repository does three things at once, and the folder numbering follows that order.

**Preserve discovery.** Ideas arrive in conversation, in argument, in false starts and corrections and sudden reversals. That process is evidence, and it is destroyed by tidying. Folders `00` through `05` hold primary sources exactly as they occurred, including the parts that turned out to be wrong.

**Distill understanding.** From the raw material, a smaller and more durable set of things is extracted: distinctions that let you see, principles that hold across cases, questions that refuse to close, and finally the Kernel. Folders `06` through `09` are where thinking is compressed rather than accumulated.

**Generate expressions.** Every public artifact is derived. Folders `10` through `12` are where the Architecture is rendered for particular audiences in particular forms, at whatever length and register the occasion demands.

## The canonical rule

**No public artifact may contradict the Architecture.**

The Kernel in `09-kernel/` is the canonical statement. Every bio, essay, deck, website, company narrative, course, and book derives from it. Applications are free to differ radically in tone, length, audience, and emphasis. They are not free to make a different claim about the world.

When an application cannot be written without contradicting the Kernel, that is a finding, not an inconvenience. It means either the application is wrong or the Kernel is incomplete. Resolve it in the Kernel first, then rewrite the application. Never let the two drift and hope no one notices, and never patch an application into agreement without going back to the source.

Derivation runs in one direction: source to Kernel to expression. Insight discovered while writing an application is welcome, but it enters the repository by being written into `06`, `07`, or `09`, not by living only in a deck.

## The tree

**Evidence.** Primary material, preserved rather than improved.

| Folder | Holds |
| --- | --- |
| `00-discovery-sessions/` | Conversations verbatim, as they happened |
| `01-biographical-sources/` | Resumes, CVs, career records: the raw facts of a life |
| `02-public-bios/` | Every published biography, as published |
| `03-intellectual-influences/` | The thinkers this is built on, and what specifically was taken |
| `04-case-studies/` | Projects examined through the Architecture |
| `05-essays-and-scholarship/` | Longer writing, published and unpublished |

**Distillation.** Compression, not accumulation.

| Folder | Holds |
| --- | --- |
| `06-distinctions/` | Perceptual tools: one file per distinction |
| `07-principles/` | Enduring truths about inquiry and creation |
| `08-questions/` | What remains open, deliberately |
| `09-kernel/` | The compact canonical statement |

**Expression.** Everything downstream.

| Folder | Holds |
| --- | --- |
| `10-narrative/` | The long-form unfolding: the research notebook, eventually the book |
| `11-applications/` | Rendered for a specific audience and purpose |
| `12-visual-design/` | The Architecture given visual form |
| `archive/` | Superseded work, kept rather than deleted |

Each folder carries its own README explaining why it exists, what belongs in it, and what does not. Read that README before adding to a folder.

## How to work here

- **Write the source before the expression.** If something new was learned, it belongs in `06` through `09` before it appears in a deck.
- **Never delete an idea.** Move it to `archive/`. Abandoned paths are frequently where later insight comes from.
- **Keep provenance.** A claim that cannot be traced to a source loses its authority even when it is true. Note where things came from.
- **Preserve the mess in the evidence folders and demand rigor in the distillation folders.** Both are correct in their place; confusing them damages the repository in one direction or the other.
- **`TODO.md`** in this directory tracks active work.

The repository is designed to be legible to a person arriving years from now with none of the context, including a later version of its author.
