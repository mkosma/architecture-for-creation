# Archive

Superseded work, kept.

## Why this exists

**Never delete ideas. Archive them.**

An abandoned path was abandoned for a reason that made sense at the time, and the reason is frequently wrong. A distinction that was too crude in 2026 may be exactly right once a later distinction gives it something to attach to. A draft discarded for being unfocused may contain the one honest paragraph that the focused version lost. A dead end is a mapped region of the space, and mapped-and-rejected is a different thing from unexplored.

There is a second reason, specific to a repository whose subject is creation. How a body of thought developed is part of what it knows. Deleting the superseded versions leaves a record that shows only conclusions, which quietly misrepresents the process as tidier than it was. That would be a strange failure in a project arguing that creation begins with reality.

Deletion is also asymmetric. Keeping a bad draft costs storage. Discarding a good one costs it permanently, and the loss is usually discovered years later.

## What belongs here

- old drafts, superseded by later ones
- previous Kernel versions
- principles and distinctions that were displaced
- dead ends and abandoned directions
- historical artifacts that no longer belong in an active folder

Archive with context. A file whose reason for retirement is unrecorded is nearly useless later, because the future reader cannot tell whether it was wrong, premature, or simply replaced. A single line stating what superseded it and why is enough, and it is what makes the archive worth revisiting.

Preserve the original date alongside the date of archiving. Both matter.

## What does not belong here

Not raw sources. Transcripts in `00-discovery-sessions/` and evidence in `01` through `05` are never superseded, because they are records of what happened rather than attempts at a claim. They stay where they are permanently.

Not work that is merely inactive. A question that has been open for two years is doing its job in `08-questions/`. A case study not yet written is not archived, it is unstarted. This folder is for things displaced by something better, not for things waiting.

Not the mechanism of storage. Git already retains every version of every tracked file. This folder is for work deliberately set aside and kept legible, which is a different function from version control and is not replaced by it.

## How it relates

Receives from everywhere. Every active folder eventually sends things here, and none of them are diminished by it.

Read it when something is stuck. A problem that will not resolve has often been approached before, from a direction that was set down too early.
